# Buendia — Agent guide

Buendia is a hosted runtime for single-file HTML apps generated by AI assistants.
The HTML lives on Buendia; the app's *data* lives in a backend the user owns.

- Build plan: [MVP.md](./MVP.md)
- Contract: [CONSTITUTION.md](./CONSTITUTION.md)
- Broken-down work: [backlog/](./backlog)
- Architectural decisions: [decisions/](./decisions)

## Read before substantive work

Open [CONSTITUTION.md](./CONSTITUTION.md) in full before:

- Adding or changing any capability listed (or not yet listed) in the Platform Registry
- Touching the control-plane data model, RLS policies, JWT claims, or sharing logic
- Changing the SDK surface, its transport, or how it resolves configuration
- Anything that affects how user data is stored, accessed, exported, or deleted
- Any change that could create drift between SaaS and self-hosted parity

For typo-level edits or copy tweaks, skip it.

## The eight principles, by name

The constitution enumerates eight binding principles. Cite them by number in PR
descriptions when they apply.

1. **Portability over convenience** — the HTML is the durable artifact.
2. **The platform is opt-in at runtime** — `__APP_CONFIG__` or setup overlay.
3. **The user owns the database** — app data lives in the user's backend.
4. **Real auth, not URL obscurity** — per-user JWTs, granted to people.
5. **Single codebase, two deployments** — SaaS and self-hosted from one repo.
6. **The SDK is a library, not a runtime** — no framework, no build step.
7. **Sharing is access, not ownership transfer** — no fork, no onward share.
8. **The stack, not the vendor** — open protocols, compatible substitutes welcome.

## Hard invariants

Drawn from `CONSTITUTION.md` §Architecture Invariants. These do not negotiate:

- Two backends. Control plane (ours) and app data (user's) are never mixed.
- Every table in an app schema gets RLS. The provisioner refuses schemas that disable it.
- The SDK has zero privileged operations. Anything DDL or admin runs server-side.
- Every provisioning action has a documented inverse.
- Buendia's servers never read app data at rest.

## Workflow

- Branch naming: as instructed in the task prompt. Develop and push there.
- Backlog tickets live in `backlog/`. Each file is one unit of work. Close by
  moving the file to `backlog/done/` in the same commit that lands the work.
- Architectural decisions go in `decisions/` as numbered ADRs (`0001-…md`).
  Open an ADR before changing `CONSTITUTION.md`, `CLAUDE.md`, or any other
  ADR. Agents do not autonomously modify governing docs.
- Commit messages: imperative mood, focus on the why. No model identifiers in
  commits, PR titles, code comments, or any pushed artifact.

## Permanently out of scope

Pushback is required if a request asks for any of these:

- Multi-file apps. Single HTML only.
- Server-side code uploaded by users.
- AI generation inside the platform.
- An app marketplace, gallery, or public discovery surface.
- Reading app data on Buendia's servers.

Flag the conflict and stop before implementing.
